# CV-5: каноническая локальная валидация

Эта папка — единая точка входа в пятифолдовую проверку основной серии решений.
Распределение строк по фолдам остаётся в `validation/`, чтобы не менять пути
уже воспроизведённых экспериментов.

## Основной исторический протокол

`grouped_text_v1` содержит пять фолдов для всех обучающих строк:

- стратификация выполняется внутри категории по бинарной метке;
- строки с одинаковым нормализованным `name + description` группируются;
- seed и число фолдов зафиксированы;
- каждый объект получает OOF-прогноз ровно один раз;
- порог, веса слияния и чекпоинт внешнего фолда выбираются только по остальным
  четырём фолдам.

Файлы протокола:

- [`../../validation/grouped_text_v1/folds.csv`](../../validation/grouped_text_v1/folds.csv) — `id`, `category`, `label`, `fold`, `group_hash`;
- [`../../validation/grouped_text_v1/basket.csv`](../../validation/grouped_text_v1/basket.csv) — быстрая проверка, которая не заменяет полную CV-5;
- [`../../validation/grouped_text_v1/manifest.json`](../../validation/grouped_text_v1/manifest.json) — число строк, версии и SHA;
- [`../../validation/build_folds.py`](../../validation/build_folds.py) — воспроизводимый скрипт построения.

```bash
python validation/build_folds.py \
  --data /path/to/train.csv \
  --output validation/grouped_text_v1/folds.csv \
  --basket-output validation/grouped_text_v1/basket.csv \
  --manifest-output validation/grouped_text_v1/manifest.json
```

Скрипт следует запускать только для проверки воспроизводимости или при создании
**новой** версии. Существующую раскладку нельзя незаметно перестраивать:
изменение строк, seed, группировки или алгоритма требует нового идентификатора
версии.

## Более строгая проверка переноса

Историческая CV-5 не полностью изолирует близкие товарные семейства. Поэтому
новые архитектуры дополнительно проверяются на
[`semantic_family_v3`](../../validation/semantic_family_v3/): связанные
семейства не пересекают фолды разработки, а отдельная контрольная выборка не
участвует в подборе.

Практическое правило:

1. `grouped_text_v1` сохраняет сопоставимость с историей и позволяет повторить основной OOF;
2. `semantic_family_v3` проверяет перенос на связанные товарные семейства;
3. один или два фолда используются только для раннего отсева;
4. финальный кандидат обязан пройти все пять фолдов и независимую проверку
   схемы и времени работы.

## Методологические запреты

- нельзя выбирать порог или чекпоинт по меткам проверяемого фолда;
- нельзя менять порядок или состав строк между вариантами абляции;
- нельзя объявлять результат одного фолда полной CV;
- нельзя смешивать результаты разных версий данных и оценки в одну дельту;
- нельзя использовать Public как цикл тонкой настройки.

Подробный аудит ограничений и дополнительных критериев:
[`../../docs/validation.md`](../../docs/validation.md).
