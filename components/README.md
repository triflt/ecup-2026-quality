# Реестр компонентов решения

`registry.json` хранит отдельные обученные компоненты независимо от архивов отправки. Для каждого компонента записаны источник, контрольная сумма, базовая модель, обучающая выборка, способ обучения, известные результаты, совместимость и эксперименты-потребители.

Правила:

1. Обученный компонент получает неизменяемый `component_id`; новый seed, корзина или рецепт создают новый компонент.
2. Тяжёлый файл не копируется в git. Реестр указывает его канонический локальный путь и SHA-256.
3. Архив отправки содержит `composition.json`, где перечислены базовое решение и точечные замены.
4. Результат ансамбля не приписывается отдельной компоненте: в карточке различаются самостоятельная оценка и оценка внутри конкретной композиции.
5. Компонент нельзя заменить, если не совпадают базовая модель, целевые модули LoRA, preprocessing и интерфейс выхода.

Так можно независимо комбинировать текстовый классификатор, embedding-классификатор, Qwen3-VL, разные Qwen3.5-адаптеры и семейные правила, сохраняя точную родословную каждого архива.
