# 620: semantic-v3 evidence-aware disagreement router

Статус: **отклонён на заранее зафиксированном экране folds 0/3**. Пять
содержательных hypothesis-shards вычислены после физического удаления labels,
sealed-строк и обученных на соревновании адаптеров из runtime.

## Проверяемый механизм

Ошибки `190/400` сосредоточены не только у общего порога, а в конкретных
семантических различиях: является ли товар БАД или обычным продуктом, продаётся
ли топливо или только пустое оборудование, входит ли горючий предмет в комплект
или упомянут как внешний расходник. Эксперимент проверяет малый маршрутизатор,
который может предложить изменение решения только когда одновременно выполнены
четыре условия:

1. binary-normalized support score одной из заранее записанных гипотез не ниже
   `0.90`; низкий score не трактуется как доказательство обратного решения;
2. extractor `490` находит точный прямой фрагмент в пользу решения, concept
   совместим именно с этой гипотезой, а фрагмент сохранился после усечения model
   input;
3. хотя бы один независимый компонент — robust base или Qwen3-VL — голосует в
   ту же сторону;
4. предложение расходится с неизменённым category route `400`.

Если прямые основания поддерживают обе стороны, offsets не совпадают с
нормализованным текстом или найден только признак отсутствия, строка получает
отказ от вмешательства. Отсутствие найденного текста никогда не считается
доказательством для смены решения.

Это переносит два известных подхода в узкую проверяемую форму: ERASER требует
связывать решение с достаточным фрагментом входа, а CLARITY — с закрытым
понятным концептом. В отличие от `490`, доказательство здесь не только текст для
жюри, а обязательный предохранитель редкой смены решения. В отличие от
отклонённого score-only gate `330`, одних вероятностей ансамбля недостаточно.

## Что заморожено до результатов

- десять гипотез, закрытый набор прямых концептов и запрещённые признаки
  отсутствия записаны в `frozen_router_spec.json`;
- старые OOF `190/260/400` запрещено подавать в обучаемую голову: оценка
  donor-строки могла быть получена моделью, обученной на текущем outer holdout;
- обучаемой категорийной головы нет: robust/Qwen3-VL используются только как
  внешний предохранитель вмешательства, а не как признаки для fit;
- пороги, screen и full acceptance gates не подбираются сеткой;
- sealed holdout недоступен builder, runtime и evaluator.

Заморожен открытый `Qwen/Qwen3.5-4B` точной ревизии из
`backbone_compatibility_decision.json`. Синтетическая русская проверка прошла:
hidden size `2560`, peak GPU memory `9.33 GB`, модель и evidence-head возвращают
конечные значения, русские offsets корректны. Проверка не читала ни одной
строки соревнования и не измеряла качество; score остаётся условным отношением
двух logits, а не калиброванной вероятностью.

## Подготовленные независимые стадии

### 1. Label-free evidence manifest

Builder читает из физически выделенного development CSV только `id`, категорию,
название и описание. Из semantic-v3 registry он читает только membership и
групповые поля через `usecols`; колонка label не загружается. Для каждого товара
extractor `490` запускается отдельно для обоих возможных решений. В JSONL
сохраняются только concept, точный фрагмент, источник и offsets — без label и
без полного текста карточки.

```bash
python experiments/620_semantic_v3_evidence_disagreement_router/build_evidence_manifest.py \
  --development-data /path/to/physical-development-only/data.csv \
  --output-dir /path/to/new/exp620-evidence
```

Preflight требует ровно 11 118 development-строк, ноль sealed-строк, ноль
ошибок offsets, ноль неразрешённых конфликтов, ноль absence-концептов как
оснований для смены решения и хотя бы 15% прямого покрытия в каждой категории.
Builder отказывается перезаписывать непустую папку.

Label-free прогон на полном development прошёл: `11 118/11 118` строк, ноль
ошибок offsets и неразрешённых конфликтов. Прямое evidence найдено для 77,05%
БАД и 56,23% flammable. Ещё 2 319 признаков отсутствия были явно заблокированы,
а 1 550 неоднозначных случаев extractor перевёл в отказ от вмешательства.
Публичная сводка находится в `analysis/evidence_manifest_preflight.json`; сырой
JSONL с товарными фрагментами в Git не добавлен.

### 2. Нулевая проверка маршрута

`evaluate_null_control.py` сохраняется как историческая проверка старого route
`400`. После результата `603` он больше не является acceptance-базой: category
specialist не перенёсся на semantic-v3. Текущий `evaluate_router.py` берёт
checksum-bound `original_route_baseline` эксперимента `603` и требует, чтобы
каждое изменение имело high-support hypothesis, совместимый exact span и
независимый естественный component vote.

### 3. Label-independent scoring и замороженный router

Обучаемая метаголова удалена: обычные OOF-признаки дали бы утечку второго
уровня, потому что donor-модели могли видеть labels проверяемого outer fold.
Базовая открытая модель оценивает только пять гипотез с совместимым evidence.
Предфильтр сократил работу с `55 590` возможных пар до `1 563` содержательных.
Router меняет решение только по неизменяемой логике выше; labels появляются
впервые в локальном CPU-evaluator.

Screen на folds `0/3` разрешает полный аудит только при положительной delta на
каждом fold. Полное принятие по-прежнему требует не меньше `+0.003` Macro F1,
победы `4/5`, отсутствия падения обеих категорий, отношения исправлений к
ухудшениям не ниже `1.5`, component-bootstrap `P(delta>0) >= 0.90` и
положительного эффекта на singleton, repeated и post-prior срезах. Большой
учитель, псевдометки и внешние sentence embeddings не используются.

## Итог строгого экрана

Evidence preflight и compatibility probe получили `GO`. Первая техническая
пятёрка не допускается к метрике: её контракт не связывал output с точной
ревизией backbone и очищенным runtime. Следующая строгая пятёрка вычислилась,
но приёмка до чтения scores отклонила object-массивы строк. Исправление меняло
только сериализацию на fixed-width Unicode и добавляло SHA-256 scorer.

Исправленные пять shards прошли целостность, после чего раскрыт только
заранее разрешённый экран folds `0/3`:

- delta fold 0: `-0,058312`;
- delta fold 3: `-0,113318`;
- средняя delta: `-0,085815`;
- исправлено 2 решения, ухудшено 39;
- flammable F1 delta: `-0,173787`.

Оба fold отрицательны, поэтому экран получил `NO_GO`. Полная оценка остальных
folds запрещена протоколом и не раскрывалась. Гипотеза о безопасной смене
решения по бинарно нормированному support score отклонена; exact-span evidence
остаётся полезным для объяснений, но не должно само управлять verdict.
