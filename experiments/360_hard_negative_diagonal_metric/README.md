# 360: обучаемая hard-negative метрика товарных семейств

## Гипотеза

Глобальные линейные heads и наивные centroid/nearest методы уже отклонены. Здесь
проверяется другой механизм: по сложным парам независимых connected-семейств
обучается диагональная метрика Qwen3-VL embedding, которая усиливает координаты,
отделяющие визуально близкие семьи с противоположными метками.

Foundation-model pass не добавляется: embedding уже вычисляется в `190`.

## Замороженный stage-1 рецепт

- только 11 207 connected-safe строк; unsafe не donors и не меняются;
- один нормированный prototype на connected family; mixed-label families
  исключаются из donors, но остаются во внешней оценке;
- для каждого donor prototype берётся один ближайший prototype той же метки и
  один ближайший противоположной метки в исходной геометрии;
- logistic pair model учится различать same/opposite по абсолютным разностям
  2048 координат; веса метрики равны положительной части `-coefficient`;
- сохраняются 256 наиболее информативных координат;
- внешний score — средняя cosine-близость к трём ближайшим positive prototypes
  минус близость к трём negative prototypes;
- `190` меняется только если знак metric score спорит с baseline и абсолютная
  уверенность входит в верхние 2% внешнего category batch; selector не использует
  метки;
- random state `36042`, LogisticRegression `C=0,1`, recipe не подбирается по
  внешним folds.

Stage 1 принимается только при Macro `>= +0,001`, минимум `4/5` побед,
corrected:regressed `>= 1,5`, отсутствии падения категории больше `0,005` и
component-bootstrap `P >= 0,80`. Только после этого запускаются три repeated
connected topology, priors replay и runtime smoke. Иначе ветка закрывается без
full refit и пакета.

## Итог stage 1

Замороженный gate отклонён: learned metric расходится с `190` на 730 safe-строках,
но ни одно расхождение не входит в верхние 2% уверенности всей категории. Поэтому
изменений и прироста нет; repeated gate по этому рецепту не запускается.

Диагностический, не селекционный срез показал асимметрию: у BAD верхние 10%
metric-разногласий дают 16 исправлений против 49 ухудшений, а у flammable — 7
против 2. Это не результат `360` и не разрешение на пакет. Flammable-only правило
перенесено в новый эксперимент и должно заново обучить метрику на других connected
topology; BAD этой веткой больше не меняется.
