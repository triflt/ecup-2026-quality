# 683: Gemma 4 E4B, LoRA только для класса

Статус: **терминально отклонён на frozen screen; folds 1/2/4, refit, упаковка и Public запрещены**.

## Гипотеза

Меняется одна модельная архитектура: `Qwen3.5-4B` из контроля `641` заменяется на
`google/gemma-4-E4B-it`. Обучающий мультимножитель, внешние folds, бинарный BCE,
seed, одна эпоха, эффективный batch 16, learning rate и нулевой порог остаются
неизменными. Gemma использует свой официальный процессор, но получает те же
первое изображение, название, описание, правило и atomic-ответ `0/1`.

Механизм — архитектурно независимая компактная мультимодальная модель может
иначе ранжировать редкий класс «Легковоспламеняющиеся». Если сигнал подтвердится,
Gemma заменит Qwen только для этой категории; прогнозы БАД останутся побайтово
равны контролю. Это продолжает подтверждённую в `659` идею категорийного маршрута,
но проверяет пригодную для исполнения модель, а не запрещённый 27B-учитель.

Официальный precedent и API: <https://huggingface.co/google/gemma-4-E4B-it>.

## Защита честности

- runtime является точной копией immutable `641`: 4 892 обучающих occurrences,
  те же folds 0/3, те же SHA и ноль validation labels;
- LoRA разрешена ровно на 132 текстовых attention-проекциях; зрительная и
  аудиочасть не обучаются;
- порог `0`, веса и маршрут не подбираются;
- sealed и Public не читаются;
- первый запуск — ровно один H100 и две реальные train + две label-free
  validation строки;
- smoke обязан выполнить forward, backward, optimizer step, сохранить и снова
  загрузить адаптер, проверить совпадение score и ZIP-контракт.

## Frozen screen gate

После принятого smoke открываются только folds `0/3`. Кандидат отклоняется, если
хотя бы один fold не улучшает tie-aware PR-AUC опасного класса или routed Macro
F1; средние минимумы `+0.005` AP и `+0.0015` Macro; FN не растут; отношение
исправлений к ухудшениям не ниже `1.5`; БАД в route должен быть идентичен `641`.
Public и folds `1/2/4` до прохождения gate запрещены.

## Терминальный результат

Технический smoke и оба screen-артефакта прошли полный аудит: нативный
`Gemma4ForConditionalGeneration`, ровно 132 текстовых LoRA-проекции, точная
привязка к runtime, конечные loss/gradients/scores, save/reload parity и пик
памяти не выше 18,1 GB (16,8 GiB).

Tie-aware AP редкого класса выросла на fold 0 с `0,787163` до `0,873396`, на
fold 3 с `0,921570` до `0,935062`; средняя delta `+0,049863`. Однако routed
Macro на fold 0 лишь совпала с контролем, а на fold 3 выросла на `+0,006455`.
На двух folds суммарный Macro вырос `0,920290 → 0,923437`, F1
легковоспламеняющихся — `0,887324 → 0,893617`; БАД остался побайтово
неизменным. FN редкого класса остались `5`, FP снизились `11 → 10`, но
отношение исправлений к ухудшениям равно только `6/5 = 1,2` при требовании
`1,5`. На singleton-семействах получено `6/2`, net `+4`.

Решение — `REJECT_AT_SCREEN`. AP-сигнал можно использовать только как основание
для новой заранее зарегистрированной гипотезы ранжирования; нельзя подбирать на
этих folds порог, калибровку или вес Gemma.
