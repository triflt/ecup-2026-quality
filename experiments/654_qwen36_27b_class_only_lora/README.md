# 654: Qwen3.6-27B LoRA только для класса

Статус: **как общая замена 4B отклонён; как компонент принятого маршрута 659
открыт для folds 1/2/4**.

Это fallback большой обучаемой модели после повторных инфраструктурных сбоев
Qwen3.8. Qwen3.6 использует зрелый runtime, уже проверенный в `651`; качество
prompting Qwen3.6 было хуже Qwen3.8, но supervised LoRA является отдельной
гипотезой и оценивается заново.

## Одно изменяемое различие

Контроль — `641` (Qwen3.5-4B class-only). Сохраняются:

- те же выбранные training occurrences и их кратность;
- тот же первый снимок, название, описание и категорийное правило;
- seed 42, один epoch, rsLoRA rank 16, learning rate `2e-4`;
- effective batch 16 и порог 0;
- folds `0/3` как экран, затем `1/2/4` только при прохождении gate.

Меняется модель: `Qwen3.5-4B → Qwen3.6-27B`. Для памяти используется
model-parallel размещение замороженных весов на четырёх GPU и схема
micro-batch 1 / accumulation 16. Каждая строка сохраняет вес `1/16`, а для
4 892 training occurrences выполняется 306 optimizer steps — столько же,
сколько в контроле `641`.

Prompting-результат `651` не используется для настройки обучения. Public и
sealed rows не читаются.

## Gate

Сначала обязателен технический успех `653`. Затем folds `0/3` должны оба дать
положительную delta к `641`; средняя delta не меньше `0,0015`, падение любой
категории не хуже `−0,002`, отношение исправлений к ухудшениям не меньше `1,5`,
опасные пропуски не растут. Только после этого открываются остальные folds.

```bash
python experiments/654_qwen36_27b_class_only_lora/build_runtime.py --help
python experiments/654_qwen36_27b_class_only_lora/train_fold.py --help
python experiments/654_qwen36_27b_class_only_lora/verify_artifact.py --help
```

Первая отправка была отклонена до создания задачи из-за ограничения размера
локального вложения. Это ошибка доставки, а не обучения. Неизменённые runtime-
пакеты были размещены как новые объекты в разрешённом пользовательском хранилище;
после audit и dry-run оба fold запущены по URL. Научный контракт не менялся.

## Результат

Оба четырёх-GPU обучения завершились, а их новые локальные копии прошли ZIP,
SHA-256, внутренний report SHA, adapter manifest, контракт, точное покрытие
`2224 + 2224` строк, finite-score и проверку отсутствия labels, sealed и Public.
При неизменном нулевом пороге кандидат улучшил Macro F1 на обоих folds:
`+0,017470` на fold 0 и `+0,023831` на fold 3, среднее `+0,020650`.

Это улучшение почти целиком относится к категории
«Легковоспламеняющиеся»: её объединённый F1 вырос с `0,816901` до `0,860927`,
а false negatives сократились с 10 до 3. Одновременно БАД снизился с
`0,953187` до `0,950267` (`−0,002920`), на fold 3 падение составило
`−0,005262`; исправлено 53 решения против 57 ухудшенных. Поэтому не пройдены
два заранее записанных guardrail: максимальное падение категории `0,002` и
отношение исправлений к ухудшениям `1,5`. Полные folds `1/2/4` не открываются
для исходной гипотезы полной замены.

Вывод не в том, что 27B бесполезна: она даёт сильный сигнал именно для редкого
опасного класса. Но текущая общая class-only версия не является устойчивой
заменой 4B. Возможная категорийная маршрутизация должна быть отдельной будущей
гипотезой с новым ID и новым frozen gate, а не ретроспективным ослаблением 654.

Эта отдельная гипотеза оформлена как 659: для БАД сохраняется 4B, а для
легковоспламеняющихся берётся заранее фиксированное среднее логитов 4B/27B
`0,5/0,5`. Она прошла все frozen gates на folds 0/3: средняя Macro delta
`+0,048812`, corrected/regressed `17/3`, false negatives `10 → 2`. Поэтому
оставшиеся 27B-folds разрешены только при наличии неизменённого audit 659.
Runner проверяет этот audit до чтения runtime; веса, порог, данные и рецепт
обучения 654 не меняются. Артефакты остаются компонентами 654, а полная оценка
маршрута относится к 659.
