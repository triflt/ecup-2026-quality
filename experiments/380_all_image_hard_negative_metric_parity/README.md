# 380: production-parity all-image hard-negative metric

## Гипотеза

Проверить тот же заранее зафиксированный flammable-only механизм, который дал
положительный средний сигнал в `370`, на embedding-представлении, совпадающем с
production-компонентом `190`: все доступные изображения товара вместо только
первого изображения.

Это отдельный follow-up, а не продолжение внешней проверки `370`: правило top 10%
уже было выбрано по предыдущему эксперименту. Поэтому результат считается
кандидатным подтверждением production parity, но не полностью независимой
валидацией.

## Замороженный протокол

- источник embeddings: собственная успешная задача
  `ecup-qwen3vl-embed-train-r2-260819`, без ограничения `max-images`;
- все три `connected_family_repeated_v1` topology;
- fold-local обучение метрики только на flammable donors;
- BAD, unsafe и non-flammable строки неизменны;
- меняются верхние 10% разногласий метрики с production-решением `190`;
- критерии принятия полностью совпадают с `370`.

Даже при прохождении offline gate перед отправкой обязательны full refit,
production integration, replay downstream priors и runtime smoke.

## Итог

All-image представление сохранило положительное среднее, но не сделало правило
устойчивым:

- Macro delta: `+0,002650`, `+0,001486`, `−0,001105`;
- среднее `+0,001011`, победы `6/15`;
- исправлено 15 решений, ухудшено 10;
- bootstrap `P(delta > 0)`: `0,7628`, `0,6692`, `0,3850`.

Формальный gate не пройден, поэтому full refit и submission не создаются. Вместе
с `370` это указывает на слабый воспроизводимый сигнал, но одиночная метрика
нестабильна к составу donor families. Следующая ветка должна стабилизировать
обучение заранее заданным ансамблем семейных подвыборок, не меняя порог по
увиденным результатам.
