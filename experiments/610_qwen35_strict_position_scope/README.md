# 610: strict position-only transaction-scope augmentation

Статус: **NO-GO до GPU**. Новая версия парсера закрывает четыре известных
класса ошибок эксперимента `500`, но на независимых ID из folds `1/2/4`
получилось только **91** допустимое преобразование. До результатов был
зафиксирован минимум 100 независимых пар и цель 200, поэтому ручные оценки не
придумывались, folds `0/3` не открывались и ни одна GPU-задача не запускалась.

## Чем 610 отличается от отклонённого 500

Версия `500` переносила предложение при слишком широком правиле и прошла ручной
аудит лишь на `62/73 = 84,93%`. Все 11 ошибок относились к четырём причинам:
несколько отношений в одной фразе, эксплуатационное «без спичек», зависимость
следующей фразы от анафоры и неявный объект.

`transaction_scope_position_strict_v2` был разработан только на этих 73 старых
строках и не использовал метки или прогнозы. Он:

- не считает общее `без X` признаком комплектации;
- требует ровно один глагол отношения в cue-предложении;
- отклоняет слишком длинные фрагменты с повреждёнными границами предложений;
- отклоняет перенос перед анафорой вроде «это», «внутрь» или «при этом»;
- требует явный содержательный объект, а не «набор 2 штуки».

Повторная механическая проверка старых данных блокирует `11/11` известных
ошибок и сохраняет eligible `49` из 62 старых успешных преобразований. Это лишь
development guard, не новая оценка качества.

## Независимый blind gate

Acceptance-pool строится только из development folds `1/2/4`, исключает все 73
ID старого аудита и читает из CSV только `id`, категорию, название и описание.
Колонка label и model outputs не загружаются. Детерминированная стратификация по
типу отношения и длине дала:

- independent eligible pool: **91**;
- target: 200;
- frozen minimum: 100;
- ручных оценок: 0;
- решение: `NO_GO_INSUFFICIENT_INDEPENDENT_PAIRS`.

Сводка без сырых товарных текстов находится в
`analysis/preflight/blind_audit_provenance.json`. Сам CSV с парами является
локальным артефактом данных и в Git не хранится. Повторно построить его можно:

```bash
python experiments/610_qwen35_strict_position_scope/blind_audit.py build \
  --runtime-dir /path/to/experiment-600/development-runtime \
  --legacy-audit experiments/500_transaction_scope_position_aug/analysis/semantic_audit.json \
  --output-dir /tmp/exp610-blind-audit
```

Если появится новая версия данных или отдельно замороженный parser v3 и pool
станет не меньше 100, два рецензента независимо заполняют `reviewer_a` и
`reviewer_b` значениями `preserved`/`rejected`. `score` разрешает обучение
только при strict pair pass не ниже 98% и Cohen κ не ниже 0,80. Неопределённая κ
не считается успехом.

## Неизменяемый обучающий контракт

Подготовленный wrapper использует только физически выделенный development
runtime эксперимента `600` и требует selector protocol
`semantic_v3_robust_base_strict_nested_v2`. Sealed holdout отсутствует во всех
входах задачи. Exact parent — Qwen3.5 specialist `260`, который в решении `400`
маршрутизируется только в категорию «Легковоспламеняющиеся».

Единственное изменение — description некоторых outer-train строк. Полное
предложение переносится в начало description, то есть сразу после отдельного
поля title в исходном prompt. Символы и токены сохраняются как мультимножество.
Training record order, ID sequence, labels, category sequence, multiplicities,
optimizer steps, seed, prompt, LoRA и все остальные параметры имеют контрольные
суммы до изменения. Детерминированный subset-sum выбирает максимально близкую к
50% половину eligible occurrences; допустимая ошибка округления — не более
половины occurrence. Inference получает исходное описание без parser и без
дополнительного прохода.

`train_screen.py` требует одновременно `GO` от независимого blind audit и `GO`
от frozen manifest конкретного fold. Текущий preflight не может пройти этот
барьер, поэтому команда намеренно завершится до загрузки модели.

## Оценка, если ветка будет открыта новой версией

`evaluate_screen.py` использует semantic-v3 visual bundle `601`, exact original
и specialist baselines `600`, исходные веса route `400` и baseline-only donor
calibration. Candidate заменяет только flammable Qwen3.5 rank; BAD predictions
принудительно остаются побайтно теми же. Folds `0/3` имеют только право
отклонить: на каждом delta должна быть положительной, FN не должны расти,
исправлений должно быть больше ухудшений, а средняя delta должна быть не меньше
`+0.001`. Passing screen лишь разрешает остальные три folds.

Текущий experiment нельзя открывать ослаблением минимума 100, добавлением уже
виденных 73 ID или аудитом folds `0/3`. Допустимый reopen — новая версия parser
или дополнительные in-distribution development-данные с теми же независимыми
порогами.
