# 652: быстрый OCR для production-runtime

Статус: **контракт и критерии заморожены; запуск ожидает освобождения GPU после
полного offline-извлечения `633`**.

## Почему нужен отдельный эксперимент

`PaddleOCR-VL-1.6` в `633` обрабатывает одно изображение примерно за `17,6`
секунды. При `2 274` изображениях в официальной 600-row выборке один только OCR
занял бы около 11 часов. Он поэтому навсегда исключён из submission-runtime и
используется только офлайн:

- как качественный источник текста и координат для датасета `634`;
- как обучающая дополнительная цель для `643/644`;
- как источник сложных примеров и контроль для ручного аудита.

Основной production-вариант обязан классифицировать без OCR на инференсе.
Быстрый OCR разрешается только как отдельная опциональная ветка для проверки
визуального доказательства.

## Изменяемый фактор и контроль

- Контроль скорости: неизменный архив `140`, `228,76` секунды на 600 товарах и
  `2 274` изображениях.
- Контроль качества OCR: immutable offline-dataset `634` и слепая ручная
  выборка карточек с мелким, повёрнутым, бликующим и смешанным русско-английским
  текстом.
- Изменяемый фактор: только OCR-движок. Классификатор, веса, пороги и порядок
  изображений не меняются.

Первый кандидат — официальный PP-OCRv5 mobile detector с
`eslav_PP-OCRv5_mobile_rec`. Он поддерживает русский, белорусский, украинский и
английский. Если `eslav` теряет смешанный текст, допускается заранее записанная
проверка `cyrillic_PP-OCRv5_mobile_rec`; это отдельный кандидат, а не подбор по
внешним меткам.

Первоисточники:

- <https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.en.md>
- <https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/OCR.en.md>

## Замороженный gate

На тех же 600 товарах и всех `2 274` изображениях быстрый OCR должен:

1. завершиться не более чем за `130` секунд;
2. вместе с базовым runtime дать прогноз не более `16` минут Public и `38`
   минут Private;
3. вернуть корректную схему и ограниченные координаты для `100%` областей;
4. дать не менее `99%` технически разбираемых изображений;
5. сохранить не менее `90%` вручную подтверждённых критических фрагментов
   относительно слепого аудита;
6. иметь не более `1%` неподтверждённого текста.

После технического допуска полезность проверяется однофакторно на folds `0/3`.
Если оба fold не улучшаются или объяснения не проходят аудит, online OCR
отклоняется. Остальные folds и интеграция в `140` тогда не запускаются.

## Связь с 643/644

OCR-разметка применяется при обучении как supervision. Основной class score
считается по исходному изображению, названию и описанию и не зависит от запуска
OCR. Отдельно измеряются:

1. модель без online OCR — основной кандидат;
2. та же модель с быстрым OCR только для проверки визуального доказательства;
3. изменение класса по OCR разрешается лишь после прохождения quality и runtime
   gate этого эксперимента.
