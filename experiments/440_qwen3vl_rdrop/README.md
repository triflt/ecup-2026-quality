# 440: R-Drop для Qwen3-VL-2B

## Гипотеза

Эксперименты `410` и `420` изменяли давление классов и продолжали уже полезный
Qwen3.5-адаптер, но оба увеличили число false negatives категории
«Легковоспламеняющиеся». Следующая проверка не меняет обучающие строки и не
продолжает Qwen3.5. Вместо этого она переобучает уже проверенный независимый
Qwen3-VL-2B-компонент эксперимента `110` с устойчивым к dropout objective.

Единственный меняемый фактор: для каждой исходной обучающей карточки выполняются
два прохода с разными dropout-масками. К среднему исходному assistant-suffix CE
добавляется симметричный KL между бинарными распределениями токенов `0/1` с
фиксированным коэффициентом `alpha=1.0`. Данные, порядок записей, hard mining,
seed `42`, первое изображение 448 px, prompt, rsLoRA rank `16`, learning rate,
batch, gradient accumulation и одна эпоха совпадают с `110`.

R-Drop соответствует работе Liang et al., NeurIPS 2021: согласование двух
dropout-подмоделей ограничивает нестабильность fine-tuning. Проверяемый механизм
здесь — уменьшение fold/seed variance и ошибочной уверенности на шумных и
повторяющихся товарных семьях без нового учителя, псевдометок или class replay.

## Замороженная корзина

`analysis/training_manifest.json` фиксирует исходные SHA-256 и SHA-256
упорядоченной последовательности product id для folds `0` и `3`. Training code
заново вызывает неизменный selector `110` и прекращает работу до загрузки модели,
если число записей, unique rows или checksum отличаются. Полный refit и остальные
folds намеренно отсутствуют в manifest до прохождения reject-only screen.

## Дешёвый reject-only screen

Сначала независимо обучаются только folds `0` и `3`. В архитектуре `400`
заменяется только Qwen3-VL rank проверяемого fold; на folds `1/2/4` остаётся
исходный Qwen3-VL. Qwen3.5 маршрутизируется как в `400`: исходный адаптер для БАД,
компонент `260` для flammable. Веса `0.50/0.25/0.25` и `0.15/0.10/0.75`
не меняются, а threshold проверяемого fold выбирается без его строк.

Ветка останавливается, если:

- хотя бы один fold имеет неположительный routed Macro delta;
- средний delta меньше `+0.001`;
- любая категория падает больше `0.005`;
- растут flammable FN или FN защитной когорты ignition/pyro/charcoal;
- исправлений не больше, чем ухудшений.

Положительный screen только разрешает полный цикл; он не позволяет принять или
собрать отправку.

## Полная приёмка после screen

- полный nested five-fold Macro delta относительно `400` не меньше `+0.003`;
- не меньше `4/5` побед и падение любой категории не больше `0.005`;
- corrected:regressed не меньше `1.5`;
- flammable FN и защитная полнота не ухудшаются;
- connected-safe delta положителен, bootstrap `P(delta>0) >= 0.90`;
- повтор seed `31415` на folds `0/3` положителен на обоих folds;
- после production priors delta положителен и выживает не меньше 80% решений;
- официальный 600-row smoke сохраняет прогнозы Public/Private не выше 16/32 мин.

Только после всех условий manifest получает отдельную новую версию с folds
`1/2/4`, repeat и full refit. Пороги по Public не подбираются.

## private compute platform

Локальные presets находятся в `.local/compute/` и используют `generate_name`
`qwen-rdrop-f0` / `qwen-rdrop-f3`, по одному `h100-1x`. Они не запускаются этим
экспериментом автоматически. Модель уже проверена в private compute platform: 2.128B параметров,
6.16 с загрузки и 4.38 GiB в обычном backward. Ожидается 50–70 минут на fold;
R-Drop влияет только на обучение. При применении остаётся один прежний проход
Qwen3-VL, поэтому измеренные 10.17/24.15 минуты Public/Private не меняются.

## Итог

Null control точно восстановил `400`: разница `0,0`, изменённых решений `0`.
Короткая задача `redacted-job` зафиксировала точный порядок обучающих
строк из той же private compute platform-среды; bundle прошёл ZIP/SHA-проверку. Две первые задачи
остановились до загрузки модели из-за отсутствующего `DATA_URL`, следующая
проверка выявила различие локального и серверного генераторов случайной выборки.
Обе причины устранены без изменения гипотезы: данные подаются временной ссылкой,
а точные индексы читаются из SHA-зафиксированного selector bundle.

Обе задачи успешно завершились, архивы прошли проверку ZIP, SHA-256, состава,
рецепта и точного порядка 2 594 прогнозов на fold. Замороженный экран отклонён:

- fold 0: Macro `0,931259 → 0,895583`, разница `−0,035676`; flammable F1
  `0,913580 → 0,842105`; 18 исправлений против 24 ухудшений; flammable FN `+5`;
- fold 3: Macro `0,916676 → 0,911769`, разница `−0,004907`; flammable F1
  `0,876712 → 0,868421`; 7 исправлений против 12 ухудшений;
- среднее изменение Macro F1: `−0,020291`.

Положительным побочным наблюдением стало отсутствие роста safety-union FN, но оно
не компенсирует падение обеих категорий и обоих fold. Полный цикл, повтор seed,
обучение folds `1/2/4`, полный refit и архив отправки не создаются. Компонент
сохранён локально только для воспроизводимости.
