# 460: специализированное мультимодальное представление Qwen3-VL

## Гипотеза

Эксперименты `440` и `450` показали, что ни общая регуляризация зрительной
модели, ни фильтрация предложений по ключевым словам не решают остаточные ошибки
легковоспламеняющихся товаров. Здесь добавляется другой тип компонента:
`Qwen3-VL-Embedding-2B`, обученный строить единый вектор текста и изображения.
Это разрешённая модель на 2 млрд параметров; большой учитель не используется.

Для каждой карточки один 2048-мерный нормированный вектор строится по названию,
первым 1600 символам описания и первому изображению. На четырёх внешних fold
обучается простой линейный классификатор, пятый fold остаётся нетронутым. Для БАД
решения `400` копируются точно. Новый ранг проверяется только в flammable-маршруте
с заранее заданными долями `0,05/0,10/0,15/0,20`.

## Этапы

Сначала одна H100 проверяет загрузку модели, форму и норму вектора,
воспроизводимость и чувствительность к изображению. Только после успешной
проверки разрешено извлечение признаков для обучающего набора. Полная модель и
архив отправки создаются лишь после пятифолдовой nested-проверки, connected
bootstrap и замера времени.

## Совместимость и извлечение

Первая задача `redacted-job` успешно загрузила все 625 частей весов и
остановилась до вычисления вектора: Sentence Transformers 5.4 принимает
инструкцию через общий аргумент `prompt`, а не как поле входного словаря. Исправлен
только этот вызов; критерии, текст, изображение и чекпоинт не менялись.

Повтор `redacted-job` успешно построил векторы `3×2048`: 1,36 секунды
на три входа, пик 4,63 GiB, изображение существенно меняет вектор. Техническая
проверка ложно интерпретировала скалярное произведение двух одинаковых
`bfloat16`-векторов с нормой `0,9987` как косинус. Код теперь повторно нормирует
вектор в float32 и считает настоящий косинус; это не меняет гипотезу или данные.

Финальный smoke `redacted-job` прошёл все проверки. Полное извлечение
`redacted-job` скачало 12 971 изображение без ошибок и построило
векторы за 6,05 минуты при пике 5,86 GiB. Задача формально упала уже после
сохранения NPZ из-за сериализации `numpy.bool_` в JSON; сам ZIP и NPZ прошли
проверку. Безопасно перепакованный локальный NPZ имеет SHA-256
`63e42fcb83316ec213e455250277e4370aa85363b741c8de001ed1bf7e34b695`.

## Результат

Гипотеза отклонена:

- Macro `0,914989` против `0,931645`, разница `−0,016656`;
- flammable F1 `0,875318` против `0,908629`, разница `−0,033311`;
- строгих побед `0/5`, изменено 17 решений: 2 исправлено и 15 ухудшено;
- flammable FN `+7`, safety-union FN `+2`;
- connected-safe `−0,017368`, bootstrap `P(Δ>0)=0,0037`.

Предупреждения LinearSVC проверены отдельным расчётом: float32 и float64 дали
полностью одинаковые оценки (`corr=1`, `max diff=0`), поэтому отрицательный
результат не является численной ошибкой. Полная production-модель и архив
отправки не создаются.
