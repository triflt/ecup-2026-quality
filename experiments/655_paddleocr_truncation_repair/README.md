# 655: точечное исправление оборванных OCR-ответов

Статус: **отклонён на ограниченном smoke; полная сетка не запускалась**.

## Причина

Полный эксперимент 633 успешно обработал 49 456 изображений, однако строгий
сборщик 634 обнаружил генерации, завершившиеся на лимите 512 токенов: часть
ответов не содержит `</s>`, а часть обрывается внутри восьмитокенного блока
координат. Молчаливое удаление хвоста или публикация такого датасета нарушили бы
заранее зафиксированный контракт доказательств.

## Единственный изменяемый фактор

Только для детерминированно найденных оборванных ответов повторяется тот же
`PaddleOCR-VL-1.6`, та же revision, `Spotting:` prompt, preprocessing изображения
и greedy decoding. Меняется только `max_new_tokens: 512 → 1536`. Все исходные
результаты 633 сохраняются, а исправления выпускаются отдельным overlay с
происхождением и контрольными суммами.

Ремонт не читает классы, folds, Public или sealed membership. Строка считается
исправленной только если вывод завершён EOS, число координатных токенов кратно
восьми и существует хотя бы одна область либо канонический пустой ответ.

## Gate

Строгий скан всех исходных ответов нашёл 7 737 кандидатов: сюда входят не только
154 полностью неразбираемых ответа, но и формально разобранные ответы без EOS,
для которых нельзя доказать полноту последней области. Первая проверочная
конфигурация ошибочно назначила одному GPU 486 строк; наблюдаемая скорость
14 строк за 25 минут доказала, что она не уложится в шестичасовой лимит, поэтому
задача была остановлена до массового запуска и её результат не используется.

Новый ограниченный smoke должен был обработать 8 детерминированно выбранных
строк. Уже первые 5 дали `0/5` принятых результатов: один ответ снова достиг
лимита без EOS, остальные завершились, но содержали некратное восьми число
координатных токенов. Frozen gate требовал ноль непринятых строк, поэтому smoke
остановлен досрочно, а подготовленные 32 полноразмерных preset не запускались.

Вывод: простое увеличение длины генерации не устраняет ошибку формата на плотных
изображениях. Следующий отдельный эксперимент должен сокращать саму задачу:
детерминированно распознавать перекрывающиеся фрагменты изображения, переводить
координаты обратно в исходную систему и объединять области с fail-closed
проверкой каждого фрагмента.
Если лимита 1536 недостаточно хотя бы для одной строки, результат не смешивается
с 633: создаётся отдельный repair-вариант с ещё большим заранее записанным
лимитом только для оставшихся строк.

После полного успеха 634 повторно собирает исходные 32 сегмента с overlay 655,
проверяет 100% покрытия и нулевое число оборванных координатных блоков.

Основания: неизменяемый structured spotting contract PaddleOCR-VL-1.6 и общий
принцип fail-closed подготовки слабой разметки; это восстановление полноты
выхода, а не подбор классификационной метрики.
