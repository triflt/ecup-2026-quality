# 660: частичный OCR-набор с явным воздержанием

Статус: **принят fail-closed набор `competition_train_paddleocr_vl16_partial_v1`**.

## Зачем нужен отдельный набор

Исходный прогон 633 успешно обработал все 49 456 изображений, но строгая
проверка обнаружила ответы без EOS, неполные координатные блоки и другие случаи,
которые нельзя выдавать за надёжное доказательство. Попытки полностью исправить
их в 655–657 оказались либо неустойчивыми, либо слишком медленными для
масштабирования.

Эксперимент 660 не восстанавливает сомнительные строки. Он детерминированно
делит исходные результаты на два состояния:

- `OCR_AVAILABLE` — генерация завершена, полностью разобрана, геометрия и
  контрольные суммы корректны;
- `OCR_UNAVAILABLE` — хотя бы один строгий критерий не выполнен. Текст и
  координаты такой строки не передаются потребителю.

Это fail-closed контракт: будущая модель может выбирать доказательство только
из `OCR_AVAILABLE`, а для остальных изображений обязана воздержаться. PaddleOCR-
VL остаётся исключительно офлайн-учителем и не входит в submission runtime.

## Изменяемый фактор и критерий принятия

Относительно 634 меняется только требование полного покрытия: вместо
дорогостоящего ремонта публикуется версионированная маска доступности. Сборка
принимается, если ровно 49 456 уникальных изображений и 12 971 товар покрыты
маской, каждый доступный OCR-рекорд проходит неизменную строгую канонизацию 634,
недоступные строки не содержат OCR-текста или координат, а labels, категории,
folds, sealed и Public не читаются.

## Результат

- маска покрывает ровно `49 456` изображений и `12 971` товаров;
- `41 691` изображение (`84,2992%`) имеет статус `OCR_AVAILABLE`;
- `7 765` изображений имеет статус `OCR_UNAVAILABLE` и не раскрывает OCR-текст
  или координаты;
- доступно `459 678` канонических областей;
- у `7 861` товаров доступны все изображения, у `299` не доступно ни одного;
- 32 исходных ZIP прошли CRC, внутренние SHA и проверку идентичности строк;
- labels, категории, folds, sealed и Public не использовались;
- PaddleOCR-VL запрещён в submission runtime.

Row-level маска хранится локально в `.local/output_v1/ocr_availability.jsonl`,
её SHA-256: `4723483b8ae851048255e959b1c98dcd054f5c099aa43864e682591051fdb3ed`.
