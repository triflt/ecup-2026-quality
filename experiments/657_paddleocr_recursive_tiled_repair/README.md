# 657: рекурсивный ремонт только не прошедшего OCR-фрагмента

Статус: **smoke принят, production терминально отклонён по скорости и ошибкам;
все 16 задач первой волны отменены, вторая волна не запускалась**.

## Гипотеза

Эксперимент 656 подтвердил, что один уровень перекрывающихся фрагментов
восстанавливает большинство плотных ответов (`6/8`), но два фрагмента сами
остались слишком насыщенными и не завершили генерацию. 657 сохраняет модель,
revision, prompt, preprocessing, greedy decoding, лимит 512 токенов, исходный
набор кандидатов, начальную сетку, перевод координат и dedupe 656.

Единственное изменение: если фрагмент не проходит EOS/LOC/full-parse gate, его
неполный ответ отбрасывается, а сам фрагмент детерминированно делится пополам по
длинной стороне с 10% overlap. Деление повторяется только для failed child до
глубины 3. Успешные соседние фрагменты не пересчитываются.

## Fail-closed контракт

- каждый использованный leaf обязан завершиться `</s>`, иметь `LOC % 8 == 0`
  и полностью разбираться либо быть канонически пустым;
- ответ failed parent никогда не входит в merge;
- terminal failed leaf отклоняет всю строку и весь shard;
- tile path, depth, границы, полный ответ, confidence и SHA сохраняются;
- координаты переводятся только функцией 656, затем применяется тот же строгий
  text + bbox-IoU dedupe;
- labels, категории, folds, sealed и Public отсутствуют в runtime.

Сначала повторяется ровно тот же восьмистрочный smoke. Production разрешён
только при `8/8`, нуле terminal failed leaves, полном SHA-аудите и ручной
проверке координат/overlap. При текущем лимите 16 GPU полные 32 сегмента могут
идти только двумя волнами максимум по 16 однокарточных задач.

## Результат smoke

- принято `8/8`, ошибок строк и terminal failed leaves — `0`;
- 28 попыток по фрагментам, из них 6 failed parents были рекурсивно разделены;
- получено 304 текстовых области, 9 overlap-дубликатов удалены;
- ZIP, report, spotting, provenance, runtime SHA и строгая схема совпали;
- все координаты лежат внутри изображения, дерево рекурсии полно;
- визуально проверены оверлеи всех восьми строк: координаты и швы выглядят
  согласованно, признаков систематического сдвига нет;
- labels, категории, folds, sealed и Public не читались.

Smoke сам по себе не является датасетом 634. Полного repaired-набора 657 не
будет: production-ветка остановлена по результатам измерения ниже.

## Терминальный результат production

Через 42 минуты после запуска 16 однокарточных сегментов каждый обработал лишь
10–20 из 242 назначенных строк. Экстраполяция фактической скорости дала 8–17
часов на сегмент при жёстком лимите задачи 4 часа. Кроме того, в 13 из 16
сегментов уже было от 1 до 5 terminal failed rows; текущий fail-closed контракт
всё равно отклонил бы каждый такой shard целиком.

Это подтверждённая, а не предполагаемая причина остановки. Все 16 задач
отменены, вторая волна запрещена. Полный ремонт не масштабируется. Вместо
ослабления проверки эксперимент 660 публикует исходный строгий OCR как
`OCR_AVAILABLE`, а сомнительные строки — как `OCR_UNAVAILABLE` без текста и
координат.

## Основание

Механизм не повторяет неудачное увеличение длины 655 и не ослабляет gate 656.
Он адаптирует разрешение только по наблюдаемому техническому признаку
незавершённого label-blind ответа. Это прямое продолжение coarse-to-fine tiling:
вычисление добавляется только там, где текущая визуальная плотность доказанно
слишком велика.
