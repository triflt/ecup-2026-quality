# 510: первое изображение Qwen3-VL с пределом 672 пикселя

## Проверяемая гипотеза

В компоненте Qwen3-VL решения `400` мелкие надписи на упаковке и небольшие
детали товара могут теряться при уменьшении первого изображения до 448
пикселей. В этом опыте меняется только этот предел: 448 → 672 пикселя, а
`max_pixels` процессора становится равным `451584 = 672²`.

Модель по-прежнему получает одно и то же первое изображение с сохранением
пропорций. Не используются обрезки, увеличение резкости, распознавание текста,
остальные фотографии товара, несколько вариантов изображения, повторный
инференс или новый учитель.

## Что остаётся неизменным

Обучение выполняет исходный runner `research/qwen3vl_lora_holdout.py`. Для него
добавлены два параметра окружения с прежними значениями по умолчанию, поэтому
родительский опыт по-прежнему использует 448 и 262144. Launcher этого опыта
фиксирует 672 и 451584 и отклоняет любые изменения следующих параметров:

- Qwen3-VL-2B-Instruct, seed 42 и исходный hard selector;
- обучающие строки, их порядок и число шагов;
- prompt, предел текста, assistant-suffix loss;
- rsLoRA rank 16, alpha 32, dropout 0.05;
- AdamW, learning rate 0.0002, weight decay 0.01, batch 4 и accumulation 4;
- один проход первого изображения при обучении и проверочной инференции.

Полное обучение запрещено. Заранее объявлены ровно два проверочных fold: `0` и
`3`. Другой fold launcher не примет.

## Обязательная проверка изображений до GPU

Скрипт `audit_rendering.py` без чтения category или label детерминированно
выбирает 200 первых изображений из локального ZIP. Для каждого изображения он
дважды декодирует один и тот же байтовый источник, строит варианты 448 и 672,
проверяет совпадение исходного cover, сохранение пропорций и ошибки декодирования.
Он также считает, сколько изображений реально получает более 25% дополнительных
пикселей.

```bash
python experiments/510_qwen3vl_first_image_672/audit_rendering.py \
  --images-zip /path/to/images.zip \
  --output experiments/510_qwen3vl_first_image_672/results/rendering_audit.json
```

Разрешение двухfoldовой проверки возможно только при нуле ошибок декодирования,
совпадения cover и пропорций, а также если доля изображений с приростом более
25% не ниже 20%. Реальный локальный аудит пройден: 200 изображений, ноль ошибок
декодирования, пропорций и совпадения cover; 197 из 200 изображений (98,5%)
получили более 25% дополнительных пикселей. Этот аудит не запускает обучение.

## Двухfoldовая проверка

Команды ниже являются воспроизводимыми точками входа двухfoldовой проверки:

```bash
python experiments/510_qwen3vl_first_image_672/run.py --fold 0 \
  --data /path/to/data.csv --images /path/to/images --output-dir /path/to/fold0
python experiments/510_qwen3vl_first_image_672/run.py --fold 3 \
  --data /path/to/data.csv --images /path/to/images --output-dir /path/to/fold3
```

Гипотеза отклоняется, если хотя бы один fold не улучшился, средний прирост Macro
F1 меньше 0.001, выросло число опасных пропусков, исправлений не больше
ухудшений либо вмешательство почти не меняет входы или решения. Folds `1/2/4`,
повтор с другим seed, полное обучение и пакет отправки до прохождения этой
проверки не предусмотрены.

`evaluate_screen.py` использует проверенный evaluator маршрута `400` из опыта
`440`: восстанавливает замороженный baseline, подменяет только ранги Qwen3-VL на
готовых folds `0/3` и применяет прежние веса и вложенный выбор порога. Рядом с
каждым CSV прогнозов обязателен `lora_holdout_report.json`; оценка прекращается,
если отчёт не содержит точные значения `first_image_max_edge=672` и
`first_image_max_pixels=451584`.

```bash
python experiments/510_qwen3vl_first_image_672/evaluate_screen.py \
  --fold-0 /path/to/fold0/lora_holdout_predictions.csv \
  --fold-3 /path/to/fold3/lora_holdout_predictions.csv \
  --output-dir /path/to/screen-evaluation
```

До появления кандидатов нулевой контроль проверяет точное восстановление
маршрута без изменения ранга:

```bash
python experiments/510_qwen3vl_first_image_672/evaluate_screen.py \
  --null-control --output-dir /path/to/null-control
```

Локальный нулевой контроль пройден: среднее изменение Macro F1 равно `0`,
изменённых решений `0`, восстановленные прогнозы полностью совпали с
замороженным маршрутом `400`.

## Проверка времени

До полного цикла нужно измерить один проход готового кандидата ровно на 600
строках. `runtime_projection.py` переводит измеренное время в оценки для 1600 и
3800 строк:

```bash
python experiments/510_qwen3vl_first_image_672/runtime_projection.py \
  --elapsed-seconds 300 \
  --output experiments/510_qwen3vl_first_image_672/results/runtime_projection.json
```

Пределы: не более 16 минут для 1600 строк и 32 минут для 3800 строк. Скрипт
откажется считать официальный gate для выборки, отличной от 600 строк.

## Результат

Оба заранее объявленных fold ухудшились, поэтому ветка отклонена без полного
цикла: `-0,00718` на fold 0 и `-0,00963` на fold 3, в среднем `-0,00841` Macro
F1. Исправлено 13 решений, ухудшено 31; на fold 3 появился один дополнительный
опасный пропуск. Увеличение разрешения действительно меняет решения, но само по
себе не делает их точнее. Folds `1/2/4`, runtime probe и full train не
запускаются.
