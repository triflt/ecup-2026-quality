# 635: причинно чистая интеграция span-head 632 в полную систему 140

Статус: **полная проверка завершена; интеграция отклонена frozen gate
устойчивости, система 140 сохранена**.

Upstream 632 завершён и принят: Macro F1 компоненты `0,9108758` против
`0,8876054` (`+0,0232704`), победа `4/5` folds, corrected/regressed
`244/130 = 1,877`, flammable FN `−16`, grouped bootstrap `P=0,9659`. Эти числа
разрешают интеграционный эксперимент, но не предсказывают F1 полного ансамбля.

## Результат

Построен checksum-locked semantic-v3 OOF replay полного рецепта 140:
robust-base, Qwen3-VL и обе Qwen3.5 являются outer-fold OOF; exact/name правила
строятся только на донорских folds. В bundle нет меток и sealed-строк.

Замена Qwen3.5 на 632 улучшила полный ансамбль с `0,9104831` до `0,9165631`
(`+0,0060801`), выиграла `4/5` folds, улучшила обе категории и дала
`88/33` исправлений/ухудшений. Однако fold 4 снизился на `−0,0235619`, а
grouped bootstrap по семантическим компонентам дал только `P=0,7785` при
заранее установленном минимуме `0,90`. Усреднение старой и новой модели дало
только `+0,0034771` и `P=0,6983`.

Поэтому 632 остаётся воспроизведённым полезным исследовательским сигналом, но
ни один вариант 635 не принят в production и не разрешён к отправке. Чемпион
остаётся 140.

Последующий разбор показал конкретный механизм отрицательного fold 4. Два
независимых seed одновременно улучшают БАД и ухудшают
легковоспламеняющиеся; у 632 редкий класс меняется с `34/2/0` на `33/7/1`
по `TP/FP/FN`. В полном маршруте пять отрицательных строк с точным
`FUEL_OR_IGNITION`-фрагментом получают небольшое повышение stable-rank и
пересекают высокий порог. Repeat-правила не покрывают эти строки. Подробный
аудит и label-blind OCR-срезы находятся в
`docs/research/archive/exp632-635-span-error-audit-2026-08-23.md`.

## Проверяемый вопрос

Эксперимент проверяет не самостоятельный F1 Qwen-компоненты, а изменение Macro
F1 **полной системы 140** при замене только её Qwen3.5-сигнала. Robust base,
Qwen3-VL, финальные веса, пороги и правила по повторяющимся товарам остаются
неизменными.

Заранее фиксируются ровно четыре варианта:

1. `original_qwen35` — исходная Qwen3.5 из 140;
2. `replace_with_632` — исходная Qwen3.5 заменена на seed-repeat 632;
3. `fixed_mean_original_632` — арифметическое среднее вероятностей исходной
   Qwen3.5 и 632 до ранжирования;
4. `evidence_gated_632` — 632 заменяет исходный сигнал только когда её фраза
   является непустой точной подстрокой канонического текста, границы совпадают,
   а тип признака входит в закрытую онтологию 623. В остальных строках вариант
   побайтово использует исходную вероятность.

Ни один вес или порог не подбирается. Используются production-константы 140:

| Категория | Robust base | Qwen3-VL | Qwen3.5 | Порог |
|---|---:|---:|---:|---:|
| БАД | 0,50 | 0,25 | 0,25 | 0,27193570137023926 |
| Легковоспламеняющиеся | 0,15 | 0,10 | 0,75 | 0,953912615776062 |

Каждый компонент ранжируется stable-rank отдельно внутри `fold × category`,
что симулирует batch-level production-преобразование 140 без использования
меток. После порога применяется один и тот же donor-only replay точных/name
правил 140. Он обязан быть построен без строк целевого fold.

## Почему нельзя использовать готовый 603

603 полезен как semantic-v3 replay модельной части locked-190 route, но он:

- не воспроизводит финальный exact/name post-processing именно 140;
- использует donor-only калибровку нового порога вместо неизменного
  production-порога 140;
- прямо задокументирован как не полностью end-to-end nested meta-validation.

Подмена 140 на 603 ответила бы на другой вопрос. Поэтому evaluator 635
отвергает любой контракт с `parent_system != 140` или с источником 603.

## Replay-артефакт

`build_replay.py` собирает label-free `NPZ` и self-hashed JSON-контракт,
которые затем принимает `evaluate.py`. Bundle
должен содержать ровно development-строки semantic-v3 и следующие массивы:

- `ids`, `categories`, `folds`, `semantic_components`;
- `robust_base_score`, `qwen3vl_score`;
- `qwen35_original_logit`, `qwen35_seed632_logit`;
- `seed632_evidence`, `seed632_concept`, `seed632_char_start`,
  `seed632_char_end`, `canonical_text`;
- `prior_override` (`-1` — нет правила, `0/1` — итог правила 140) и
  `prior_source` (`NONE`, `EXACT` или `NAME`).

Контракт обязан доказать внешний OOF для каждой обучаемой компоненты, отсутствие
sealed-строк и меток в bundle, donor-only построение prior, точные SHA-256
источников и неизменность 140. Недостаточно положить в JSON готовые predictions:
evaluator самостоятельно собирает все четыре маршрута и повторно проверяет
структурную корректность evidence.

## Протокол принятия

Сначала открываются только folds `0/3`. Каждый кандидат должен улучшить оба,
не ухудшить категорию больше чем на `0,002`, не увеличить FN и дать отношение
исправлений к ухудшениям не ниже `1,5`.

Только прошедшие экран варианты оцениваются на всех пяти folds. Финальный gate:

- Macro delta не ниже `+0,003` к полному original-140 replay;
- победа минимум на `4/5` folds;
- ни одна категория не ухудшается;
- corrected/regressed не ниже `1,5`;
- grouped bootstrap по semantic components даёт `P(delta > 0) >= 0,90`;
- FN по легковоспламеняющимся и по всем положительным строкам не растут;
- 600-row runtime-report подтверждает прогноз не больше 20 минут Public и 40
  минут Private, корректную схему и неизменность прогнозов после оптимизации.

Public и sealed holdout запрещены. Компонентный F1 632 в этом эксперименте не
вычисляется и не сравнивается с F1 ансамбля.

## Научный precedent

Rakuten SIGIR 2020 и Amazon product categorization показывают пользу
низкоёмкой decision-level late fusion независимых модальностей. Здесь перенос
проверяется строже: меняется один уже существующий decision-сигнал, а все
остальные части production-системы заморожены.

## Команда воспроизведения

```bash
python experiments/635_span_head_full140_integration/evaluate.py \
  --stage screen \
  --bundle /path/to/semantic_v3_140_oof_replay.npz \
  --replay-contract /path/to/replay_contract.json \
  --accepted-632-report /path/to/accepted_632_full.json \
  --registry validation/semantic_family_v3/folds.csv \
  --output /path/to/635_screen.json
```

Полный запуск меняет `--stage full`, добавляет `--runtime-report`, но не меняет
bundle, варианты, веса или пороги.
