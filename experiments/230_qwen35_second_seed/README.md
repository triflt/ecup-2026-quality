# 230: Second-seed Qwen3.5 ensemble

## Гипотеза

Независимый rsLoRA seed снизит variance и улучшит ensemble.

## Протокол

Dataset: `competition_train_v1`. Основной evaluation protocol: `nested_grouped_v1` из `validation/registry.toml`. Frozen grouped folds лежат в `validation/grouped_text_v1/folds.csv`; global OOF и single-fold scores помечаются как диагностические.

## Схема проверки и итогового обучения

Размеченные товары заранее разделены на пять частей по товарным семействам. Карточки одного семейства остаются в одной части, поэтому модель не может получить почти тот же товар одновременно в обучении и проверке.

Для каждого seed обучаются пять проверочных адаптеров. Каждый адаптер видит четыре части и предсказывает пятую. Пять непересекающихся наборов прогнозов соединяются в один прогноз для всех размеченных строк, причём каждая строка предсказана моделью, которая её не обучала. Веса объединения и пороги для каждой проверяемой части выбираются только по остальным четырём частям. Это и есть вложенная групповая проверка `nested_grouped_v1`.

Мы не выбираем лучший из пяти адаптеров. По совокупному внеобучающему прогнозу выбирается рецепт: состав моделей, способ усреднения, веса и пороги. Для принятия рецепта требуется прирост Macro F1 не меньше `0.001`, победа как минимум на четырёх из пяти частей и отсутствие падения любой категории больше `0.005`.

Отдельный шестой адаптер каждого seed обучается на всех размеченных данных по тому же рецепту. Он не участвует в проверочной оценке. После принятия гипотезы именно полные адаптеры seed `42` и `31415` входят в архив: товар проходит через оба, их вероятности усредняются, а затем результат объединяется с прежними компонентами. Пять проверочных адаптеров нужны только для измерения качества и в отправку не входят.

## Отличие от лучшего Public-решения `190`

Текстовая модель, Qwen3-VL-Embedding, Qwen3-VL rsLoRA и правила товарных семейств сохранены. Принципиальное изменение одно: вместо одного Qwen3.5 rsLoRA seed `42` используются два независимо обученных адаптера seed `42` и `31415`, а их вероятности усредняются до смешивания с остальной системой. Независимые ошибки двух обучений частично сокращаются. Вместе с этим вложенная проверка заново выбрала веса: для БАД `0.55/0.00/0.45` для базовой оценки, Qwen3-VL и среднего Qwen3.5; для легковоспламеняющихся `0.05/0.10/0.85`.

Цена изменения — второй последовательный проход Qwen3.5. Оценка времени выросла с `10.17` до `14.23` минуты на Public и с `24.15` до `33.80` минуты на Private, но остаётся внутри абсолютных ограничений организаторов.

## Результат

Пять OOF-архивов и full-data adapter seed `31415` скачаны локально. Лучший вариант усредняет вероятности seed `42` и `31415`, после чего объединяет результат с robust base и Qwen3-VL.

- nested BAD F1: `0.9518755060`;
- nested flammable F1: `0.8865979381`;
- nested Macro F1: `0.9192367221`;
- прирост к Dual-LoRA baseline `0.9118425206`: `+0.0073942015`;
- победы по outer folds: `4/5`;
- grouped bootstrap: `P(delta > 0) = 0.8867`, 95% interval `[-0.00470, 0.02008]`.

Заранее заданные критерии принятия пройдены. Интервал bootstrap пересекает ноль из-за малого числа положительных flammable-примеров, поэтому результат принят как локальный кандидат, но ещё не как подтверждённый лидер. Однопроходное объединение и время двух последовательных Qwen3.5 проверены ниже.

На 20 одинаковых моделированиях повторяемости 70/30 точные правила текста и названия не поглотили улучшение: средний Macro F1 вырос с `0.9410916906` до `0.9426495121` (`+0.0015578214`). Это вспомогательная построчная проверка; основным доказательством остаются пять групповых разбиений.

Однопроходное точное объединение двух LoRA проверено отдельно. Матрицы изменений весов объединены без численной ошибки в адаптер ранга 32, но после нелинейной модели результат не воспроизвёл среднее вероятностей:

- nested BAD F1: `0.9534695347`;
- nested flammable F1: `0.8664987406`;
- nested Macro F1: `0.9099841376`;
- разница к прежнему Dual-LoRA: `-0.0018583830`;
- победы по folds: `2/5`;
- grouped bootstrap `P(delta > 0) = 0.381`.

Все три критерия отклонения сработали, поэтому rank-32 merge не используется. Двухпроходный архив со средним вероятностей проверен на официальном образе: 600 товаров за `320.24` секунды, `0.5337` секунды на товар, корректная схема всех результатов. Оценка Public на 1600 товаров — `14.23` минуты при лимите 20 минут; оценка Private на 3800 товаров — `33.80` минуты при лимите 40 минут. Public-запас достаточен, Private-запас меньше желаемых 20%.

Раздельный четырёхкомпонентный подбор весов отклонён: nested Macro F1 `0.9108747118`, ниже baseline. Среднее рангов двух seed дало `0.9171775905`, но уступило среднему вероятностей.

Подробные machine-readable результаты находятся в `results/metrics.json` и `reports/experiment-log.csv`.

## Public-проверка

Двухпроходный архив успешно выполнился на платформе, но получил Public Macro F1 `0.8639458233` против `0.8919244237` у `190`: разница `-0.0279786004`. Следовательно, рецепт `230` отклонён онлайн, а `190` остаётся чемпионом и финальным решением.

Эта отправка одновременно проверила среднее двух seed и заново выбранные веса компонентов, поэтому она не доказывает, что вреден именно второй seed. Следующая причинная проверка должна удерживать веса `190` фиксированными и менять только один компонент. Локальный критерий также ужесточается: результат с bootstrap-интервалом, пересекающим ноль, больше не считается достаточным для рискованной Public-отправки.
