# 410: Разнообразные отрицательные семейства для flammable-ветки 400

## Гипотеза

Маршрутизация `400` показала, что полный адаптер `260` полезен именно для категории
«Легковоспламеняющиеся»: локальный Macro F1 вырос на `0,008236`, а все 26 изменений
пережили правила семейных приоритетов. При этом прежний отбор 1 600 отрицательных
flammable-строк тратит 299–328 предъявлений на повторы точных текстовых семейств.
Отбор по одному представителю на семейство должен расширить покрытие отрицательных
причин, не меняя размер корзины и число обновлений.

## Единственный изменяемый фактор

Родитель обучения — точный рецепт адаптера `260`: семейно-разнообразные
положительные БАД, обычное пятикратное повторение положительных flammable-примеров,
те же изображения, prompt, seed, optimizer и число обновлений. Меняется только
отбор отрицательных flammable-примеров: 800 сложных и 800 случайных разных
нормализованных текстовых семейств вместо 1 600 строк.

В применении наследуется маршрутизация `400`: адаптер `190` обслуживает БАД, новый
адаптер — только flammable. Поэтому изменения БАД не могут попасть в итоговый ответ.

## Замороженная проверка

Основное сравнение проводится с `400` в зафиксированном ансамбле `190`:

- прирост Macro F1 не меньше `+0,003`;
- не меньше четырёх побед на пяти внешних разбиениях;
- `P(прирост > 0) >= 0,90` в bootstrap по связанным компонентам;
- flammable F1 должен вырасти, а число ложноотрицательных flammable-ответов — не
  увеличиться;
- на заранее зафиксированных когортах источников огня, пиротехники и угля не должно
  быть суммарной потери полноты;
- после применения production-priors должно сохраниться не меньше 80% изменений и
  итоговый прирост должен остаться положительным.

Если основной прогон проходит эти условия, seed `31415` повторяется на fold 0 и 3.
Средний прирост повторов должен быть положительным без падения больше `0,005`.

## Ограничение валидации

Трудность примеров наследует тот же OOF-скорер, что и `260`, чтобы эксперимент
оставался однофакторным. Этот скорер не полностью вложен относительно каждого
внешнего fold: модели для части обучающих строк могли видеть внешний holdout.
Поэтому результат нельзя принимать по обычным пяти folds без connected-проверки,
повтора seed и Public-подтверждения.

## Воспроизводимая обработка

`ingest_bundle.py` принимает каждый private compute platform bundle только в новый каталог и
проверяет CRC, безопасные пути, отсутствие символических ссылок, состав стадий,
размер адаптера, JSON-отчёты, число и уникальность fold-прогнозов. После появления
всех пяти folds `finalize.py` собирает одинаково ранжированные оценки `260` и
`410`, воспроизводит зафиксированный ансамбль и запускает `evaluate.py` со всеми
замороженными критериями. Полный адаптер хранится отдельно и не считается принятым
до прохождения этих критериев и повторного seed.

## Результат

Гипотеза уверенно опровергнута единой замороженной проверкой. Маршрутизированный
Macro F1 снизился с `0,931645` до `0,909148`, разница `−0,022497`; flammable F1
снизился с `0,908629` до `0,863636`, БАД по конструкции не изменился. Выиграны
только folds 1 и 3 из пяти, изменены 32 решения: исправлено 7, ухудшено 25.

Число ложноотрицательных flammable-ответов выросло на 8. В объединённой защитной
когорте источников огня, пиротехники и угля пропусков стало на 3 больше.
Connected-safe разница равна `−0,023434`, bootstrap
`P(прирост > 0)=0,0108`, а весь 95%-й интервал `[-0,04657; −0,00325]` ниже нуля.
Все изменения пережили production-priors, поэтому потерю качества нельзя
объяснить последующими правилами.

Повтор seed `31415` и сборка отправки заблокированы заранее заданными критериями.
Полный адаптер сохранён локально только как исследовательский артефакт. Практический
вывод: дополнительное разнообразие отрицательных примеров делает flammable-
специалиста слишком консервативным; следующая ветка `420` проверяет противоположное
направление — короткое сбалансированное продолжение обучения для полноты.
