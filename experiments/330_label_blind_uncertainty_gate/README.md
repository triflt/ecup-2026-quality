# 330: selective gate разногласий production-компонентов

## Гипотеза

Фиксированное объединение `190` иногда подавляет правильный независимый сигнал.
Новый gate не строит общий stacker и не добавляет модель: он может изменить ответ
только тогда, когда не менее двух уже вычисляемых production-компонентов
(`robust base`, `Qwen3-VL`, `Qwen3.5`) согласованно спорят с итогом `190` и имеют
достаточное преимущество калиброванной уверенности.

Калибровка, допустимый предел уверенности базового решения и минимальное
преимущество выбираются только на внутренних donor folds. Истинная метка внешней
строки, oracle rescue и диагностические компоненты, отсутствующие в отправке
`190`, запрещены.

## Замороженный рецепт до оценки

- входы: только три fold/category rank, уже доступные в `190`;
- четыре одномерных Platt-калибратора: три компонента и locked combined score;
- изменение возможно только при согласованном голосе против базового ответа;
- сетка: минимум `2` или `3` противоречащих компонента, преимущество уверенности
  `0/0,05/0,10/0,15`, максимальная уверенность baseline
  `0,60/0,70/0,80/0,90`, плюс обязательный no-op;
- конфигурация выбирается по inner grouped F1; равенства разрешаются в пользу
  no-op, затем меньшего числа изменений и более строгого gate;
- locked weights и пороги `190` не перенастраиваются кандидатом;
- downstream exact/name/numeric/shingle priors воспроизводятся donor-only.

## Проверка

Обязательны исторические пять folds, 11 207 connected-safe строк, три заранее
замороженные connected topology, component bootstrap и replay production priors.
Для принятия нужны: Macro не менее `+0,002`, минимум `4/5` побед на исторической и
connected-safe проверках, положительная средняя разница на всех трёх повторах,
bootstrap `P(прирост > 0) >= 0,90`, отсутствие падения категории больше `0,005`
и положительная разница после priors.

Full refit, изменение submission-кода и Public-пакет запрещены до прохождения
всех условий.

## Итог

Гипотеза отклонена:

- historical Macro `−0,000370`, побед `0/5`, 1 исправление против 9 ухудшений;
- connected-safe Macro `−0,000635`, побед `0/5`, 3 исправления против 15;
- component bootstrap на safe: `P(прирост > 0)=0,0068`, весь 95% интервал ниже
  нуля;
- все три connected-повтора отрицательны:
  `−0,000260 / −0,000446 / −0,000475`;
- после production priors разница остаётся отрицательной: `−0,000227`.

Первый численный путь Platt-калибратора выдавал многочисленные backend-warning при
конечных входах. Рецепт не менялся: revision `r1` использовал устойчивый solver и
снова дал отрицательный результат. Общий consensus production-компонентов закрыт;
следующая ветка должна добавить новый причинный признак, а не ещё один способ
голосования.
