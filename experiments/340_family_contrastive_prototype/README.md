# 340: Семейно-контрастный прототипный score

## Гипотеза

Линейный embedding-head внутри `190` сглаживает локальные различия между близкими
товарами. Дополнительный score, равный разности сходства с ближайшими положительными
и отрицательными прототипами независимых товарных семейств, может исправить
контрасты `supplement ↔ sports food` и `fuel ↔ equipment` без нового VLM-прохода.

## Единственный изменяемый фактор

В неизменный continuous score `190` добавляется ровно 5% ранга нового прототипного
score; остальные 95% сохраняют прежние веса. Для каждого внешнего fold прототипы
строятся только из остальных folds. Каждое согласованное `group_hash` представлено
одним усреднённым прототипом; семьи с противоречащими метками исключаются. Score —
разность средних cosine similarity до трёх ближайших положительных и трёх
ближайших отрицательных прототипов.

Для дешёвого screen используется фиксированная, не обучаемая Gaussian projection
2048→256 с seed `34042`. Она не видит метки и одинаково воспроизводится при
применении. Вес, число соседей и размер проекции заданы до расчёта метрик.

## Связь с сильными решениями

MOON/MOON2.0 используют семантически близкие сложные отрицательные пары для
e-commerce представлений. Победные metric-learning решения товарного matching
используют cosine neighbourhoods и независимые семейства. Здесь проверяется
минимальный переносимый вариант поверх уже вычисляемого Qwen3-VL embedding, а не
ещё один общий метаклассификатор.

## Честная проверка

- замороженные пять `grouped_text_v1` folds;
- прототипы внешнего fold не содержат ни одной его строки;
- threshold каждого внешнего fold выбирается только по остальным четырём;
- baseline — byte-identical nested predictions `190`;
- обязательны category F1, fold wins, grouped bootstrap и singleton analysis;
- принятие требует `+0.003` Macro, минимум `4/5` побед, отсутствие падения
  категории более `0.005` и `P(delta>0)≥0.90`;
- положительный screen только разрешает image-connected stress и production-prior
  replay, но сам не разрешает Public.

## Runtime

Qwen3-VL embedding уже вычисляется внутри `190`. Дополнительные операции — одна
фиксированная проекция и поиск по компактному прототипному индексу; генеративного
прохода нет. Точный runtime smoke нужен только после положительного grouped screen.

## Результат

Полный рецепт не запускался и его метрика не читалась. Независимая критика до
оценки показала две причины остановки:

1. наивный nearest-prototype без обучаемой hard-negative проекции слишком близок к
   уже отклонённым centroid/neighbor веткам;
2. в `grouped_text_v1` обнаружены две exact-text семьи, пересекающие folds: 9 строк
   суммарно. Для nearest-family метода это прямой donor→outer путь.

Эксперимент отменён до метрики. История и код сохранены, но повтор разрешён только
после connected text/image guard и как обучаемая проекция на заранее заданных
hard-negative когортах. Текущий приоритет после `310` — sports-regulatory BAD
residual head, если мягкие цели сами не закроют эту когорту.
