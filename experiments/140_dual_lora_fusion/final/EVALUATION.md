# Оценка решения 140

У решения 140 есть несколько локальных оценок, потому что они отвечают на
разные вопросы. Их нельзя выдавать за одну и ту же CV-метрику.

| Протокол | Macro F1 | Что оценивает |
|---|---:|---|
| Вложенная CV-5 с групповым разбиением | `0.9118425206` | Перенос на товары из отложенной текстовой группы; веса слияния выбираются только на остальных четырёх фолдах |
| Симуляция повторов товаров | `0.942878` | Полный рецепт с памятью точных `id` и названий, если в скрытых данных повторяются знакомые товары |
| Повторные разбиения 70/30 | `~0.94109` | Устойчивость пользы памяти на нескольких симуляциях train/test |
| Public-лидерборд | `0.8923976821` | Фактический результат неизменяемого архива решения 140 |

Первая оценка использовалась при выборе архитектуры и записана в
`experiments/140_dual_lora_fusion/results/metrics.json`. Оценки на повторах
показывают дополнительный вклад памяти обучающей выборки. Они записаны в
`reports/champion.json` и `reports/submissions.csv`.

## Текущий протокол сравнения

- `grouped_text_v1` и вложенная CV сохраняют сопоставимость с историческими
  экспериментами решения 140.
- `semantic_family_v3` используется для новых компонентов. Связанные товарные
  семейства не пересекают фолды разработки.
- Результат на одном или двух фолдах годится только для раннего отсева
  гипотезы, но не для лидерборда.
- Канонический локальный лидерборд:
  [`reports/semantic-v3-leaderboard.csv`](../../../reports/semantic-v3-leaderboard.csv).
- Public проверяет заранее зафиксированный архив, а не помогает его донастроить.

Решение 140 появилось до полного протокола `semantic_family_v3`. Его повторный
запуск с проверкой контрольной суммы записан в эксперименте 635 как строка
`original_qwen35`. Новые компоненты принимаются, только если превосходят этот
маршрут по заранее зафиксированным критериям.
