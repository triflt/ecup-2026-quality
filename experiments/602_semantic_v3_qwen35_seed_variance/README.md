# 602: разброс независимых seed Qwen3.5 на semantic-family-v3

Статус: **подготовлен, обучение не запускалось**.

## Вопрос

Эксперимент отделяет эффект случайности обучения Qwen3.5 от изменения рецепта.
`230` показал, что локальный прирост от второго seed не перенёсся на Public, но
там одновременно менялись и seed, и веса финальной смеси. Поэтому здесь рецепт
`190` сохраняется буквально: Qwen3.5-4B, первый снимок, hard selector, один
epoch, rsLoRA и исходная policy числа шагов. Меняется только начальное случайное
состояние.

Seed `42` приходит как независимая baseline-компонента из `600`. Новые задачи
ровно такие:

- seed `31415`, `271828`, `161803`;
- каждый на development folds `0`–`4`;
- всего 15 одно-GPU задач.

Ни дополнительных teacher-сигналов, ни pseudo-labels, ни новых эпох, ни
полного обучения в этом эксперименте нет.

## Строгая изоляция

Эксперимент наследует runtime wrapper `600`, а не создаёт собственную копию
данных или selector. Перед импортом parent runner wrapper `600` физически
записывает CSV только с 11 118 development-строк и проверяет, что 1 853 sealed
строки не попадут в selector, обучение или прогноз. `602` дополнительно
проверяет контракт каждого seed/fold output и использует только локальную папку
runtime inputs `600` с замороженным strict-v2 development-only selector и
provenance.

Если интерфейс или invariants `600` изменились, задача завершается до загрузки
модели. Это преднамеренный fail-closed blocker.

## Заранее объявленная оценка

Сначала каждый из трёх seed сравнивается с seed `42`; это измерение разброса,
а не выбор лучшего seed. Затем проверяется ровно один ensemble:

`p = (p_42 + p_31415 + p_271828 + p_161803) / 4`.

Веса навсегда равны `1/4`: ни seed, ни веса после результатов не отбираются.
Для каждой категории и outer fold порог выбирается только по остальным четырём
development folds тем же фиксированным quantile rule, что и у parent recipe.
Sealed holdout не участвует ни в одном из этих шагов.

Ensemble может пройти дальше, только если одновременно выполняются все условия:

- Macro F1 относительно seed `42` не ниже `+0,003`;
- минимум 4 из 5 outer folds выигрывают;
- F1 ни одной категории не падает больше чем на `0,005`;
- component bootstrap даёт `P(delta > 0) >= 0,90`;
- `corrected / regressed >= 1,5` (или regressions равны нулю).

Это acceptance для Qwen3.5-компоненты, а не разрешение немедленно менять
Public-решение `190`. После развития требуется отдельная проверка целой
production architecture без перенастройки.

## Блокер и бюджет

`600` уже подготовлен, но ожидает strict nested v2 selector scores и ещё не
произвёл baseline OOF seed `42`. Обучение трёх новых seed можно запускать вместе
с задачами `600`, как только scoped runtime готов; итоговый evaluator ждёт полную
сетку `4 × 5`. После разблокировки план требует 15 GPU-задач; историческая оценка
— 9–12,5 GPU-часов и 45–80 минут при параллельном запуске.

Результаты должны обрабатываться только командой:

```bash
python experiments/602_semantic_v3_qwen35_seed_variance/evaluate_seed_variance.py --help
```

Она откажется от неполной сетки `4 × 5`, от output без контракта или от
несовпадающих development ID/folds.
