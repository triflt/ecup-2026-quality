# 633: OCR всех изображений с координатами

Статус: **smoke пройден; полное распознавание 49 456 изображений выполняется
32 независимыми сегментами**.

## Гипотеза

Текст на упаковке содержит состав, вид топлива, отрицания и сведения о
комплектности, которых нет в названии карточки. Распознавание текста вместе с
координатами позволит модели выбирать существующее доказательство на изображении,
а не придумывать фразу или прямоугольник.

Меняется только источник визуального текста. Классификатор и веса ансамбля на
этом этапе не меняются.

## Модель

Используется `PaddlePaddle/PaddleOCR-VL-1.6`, revision
`c5630abae1d940eafe0697512a0325494b02ab42`. Это компактная модель на 0,9 млрд
параметров с отдельным режимом `Spotting:`. Он возвращает распознанный текст и
четыре нормированных угловых точки области. Официальный model card сообщает о
96,33% на OmniDocBench v1.6 и поддержке text spotting; PaddleOCR заявляет
поддержку русского письма.

Первоисточники:

- <https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6>
- <https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PaddleOCR-VL/PaddleOCR-VL-1.6.en.md>

## Контракт

1. `build_manifest.py` разворачивает исходные 12 971 строк в 49 456 записей
   `(id, image_index, url)` без чтения меток.
2. `run_spotting.py` скачивает изображение, запускает только `Spotting:` и
   сохраняет исходную генерацию, текст, четырёхугольник в координатах исходного
   изображения, размер изображения и диагностическую уверенность генерации.
3. Координаты никогда не генерируются последующей классификационной моделью:
   она сможет выбирать только одну из сохранённых OCR-областей.
4. Сначала выполняется smoke на 100 изображениях. Полный набор разрешён только
   при корректном формате не менее чем на 95% успешно прочитанных изображений и
   отсутствии выхода координат за границы.
5. Автоматическое распознавание не считается истинной ручной разметкой. Перед
   использованием доказательств обязателен отдельный слепой аудит.

## Выходная версия данных

После полного успешного прогона создаётся неизменяемая версия
`competition_train_paddleocr_vl16_spotting_v1`. До этого версия не регистрируется
как готовая.

Первый запуск остановился до модели из-за ограничения установки пакетов в
одноразовом окружении. Второй сформировал проверенный ZIP, но все 100 строк
завершились до генерации: класс процессора не экспортировал `min_pixels` как
атрибут. После чтения значения из закреплённого конфига третий smoke успешно
обработал 100/100 изображений за 1851,26 секунды и нашёл 1437 областей текста.
На 7 изображениях модель корректно вернула только `</s>` — канонический ответ
для изображения без распознанного текста. После фиксации этого fail-closed
контракта формат разбирается на 100/100, ошибок и выходов координат за границы
нет. Полный прогон запущен без меток и без изменения модели.

Независимый обзор открытых OCR-моделей не дал оснований прерывать этот прогон:
PaddleOCR-VL-1.6 остаётся лучшим единым default для text spotting с
координатами. Но опубликованного русского product-card benchmark у неё нет.
После сборки полного датасета запланирован отдельный ручной A/B на 100–300
карточках против GLM-OCR и PP-OCRv5-`eslav`; критерии и источники записаны в
`docs/research/2026-08-23-ocr-model-selection.md`.
