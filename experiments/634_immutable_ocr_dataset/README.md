# 634: неизменяемый OCR-датасет

Статус: **полная версия терминально не опубликована; ремонт 655–657 отклонён,
принят частичный fail-closed набор 660**.

## Назначение

Эксперимент не обучает модель и не читает метки. Он строго объединяет полные
shard-выходы `633`, сверяет их с исходным label-blind manifest и выпускает один
неизменяемый набор `competition_train_paddleocr_vl16_spotting_v1`.

Меняется только представление уже полученного OCR. Классификатор, разбиения,
метки и Public-результаты не используются.

## Почему нужен отдельный этап

`633` сохраняет ответ OCR по каждому изображению независимо. Перед обучением
модели выбора доказательства необходимо доказать, что:

- присутствуют все `49 456` изображений из `12 971` карточки ровно по одному
  разу;
- каждый shard относится к одной ревизии модели и одному manifest;
- четырёхугольники имеют четыре точки и целочисленные координаты `0..1000`;
- ни одна область не потеряла связь с карточкой и номером изображения;
- технические повторы не превращаются в межкарточечную дедупликацию;
- итоговые файлы можно проверить по SHA-256 без доступа к исходной среде.

Такой отдельный data contract соответствует принципам Datasheets for Datasets,
а формат четырёхугольников и семантика генерации наследуются из официального
режима `Spotting:` PaddleOCR-VL-1.6:

- <https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6>
- <https://arxiv.org/abs/1803.09010>

## Входы

`build_dataset.py` принимает:

1. неизменённый expanded manifest из `633` со строгими полями
   `id,image_index,url`;
2. все каталоги shard-выходов `633`, каждый с `spotting.jsonl` и
   `report.json`;
3. локальную схему [`ocr_image_record.schema.json`](ocr_image_record.schema.json).

Строки с `label`, `category`, `fold`, `split`, `public`, `sealed` или похожими
полями отклоняются. Ошибка обработки хотя бы одного изображения, пропущенная или
повторная пара `(id, image_index)`, несогласованный shard, неправильная ревизия
модели, повреждённая контрольная сумма либо некорректный четырёхугольник запрещают
публикацию версии.

## Дедупликация без потери связи

Объединяются только одинаковые технические повторы **внутри одной картинки**:
совпадают нормализованный текст и все четыре нормированные точки. Одинаковые
фрагменты из разных изображений и карточек всегда остаются отдельными.

У объединённой области сохраняются:

- `region_id`, содержащий стабильный `global_index` изображения;
- `id` и `image_index` родительской строки;
- исходный четырёхугольник;
- все `source_occurrences` с исходным индексом detection и исходным текстом.

Поэтому удаление технического повтора не теряет ни image-link, ни box-link, ни
вариант распознанной строки.

## Семантика уверенности

`generation_confidence.value` — геометрическое среднее вероятностей токенов всей
OCR-генерации. Оно:

- относится ко всей последовательности, а не к одной области;
- не является вероятностью правильного распознавания;
- не откалибровано;
- наследуется region только через `confidence_ref`, без копирования числа под
  видом region confidence.

Для будущего отбора OCR-доказательств это значение можно использовать только как
диагностический признак после отдельной калибровки.

## Выход

Новый каталог создаётся атомарно и никогда не перезаписывается:

- `ocr_images.jsonl` — канонические image-level записи;
- `ocr_image_record.schema.json` — точная JSON Schema;
- `merge_report.json` — глобальная полнота и структурная разбираемость без
  категорий;
- `provenance.json` — модель, исходный manifest, builder и SHA каждого shard;
- `dataset_manifest.json` — SHA-256 всех файлов и итоговый dataset checksum.

Точный проект записи в общий реестр находится в
[`dataset_registry_proposal.toml`](dataset_registry_proposal.toml). Он не
продвигается в `datasets/registry.toml`, пока полный артефакт не прошёл все gates.

## Запуск после завершения 633

```bash
python3 experiments/634_immutable_ocr_dataset/build_dataset.py \
  --manifest /path/to/633/all_images.jsonl \
  --shard-dir /path/to/shard-0 \
  --shard-dir /path/to/shard-1 \
  --output-dir /path/to/competition_train_paddleocr_vl16_spotting_v1
```

Категории намеренно отделены от сборщика. После создания набора внешний evaluator
может получить только двухколоночный файл `id,category` и сформировать лишь
агрегированный отчёт:

```bash
python3 experiments/634_immutable_ocr_dataset/evaluate_category_coverage.py \
  --dataset-dir /path/to/competition_train_paddleocr_vl16_spotting_v1 \
  --category-manifest /path/to/id_category.csv \
  --output /path/to/category_coverage.json
```

Evaluator отклоняет метки, folds, split, Public и sealed membership. Никаких
построчных данных он не выводит.

## Критерий готовности

Версия может быть предложена к регистрации только если:

- manifest покрыт на `100%`;
- ошибок обработки, отсутствующих и повторных изображений — `0`;
- malformed location-output и областей вне `0..1000` — `0`;
- все входные и выходные SHA-256 проверены;
- bundle повторно проходит `--verify-only`;
- Public и sealed данные или членство не читались.

Первая изолированная сборка была остановлена проверкой SHA: прямой HTTP-адрес
артефакта требовал авторизацию и возвращал не исходный ZIP. Нативное подключение
выходов предыдущих задач устранило эту проблему без изменения данных. Второй
проход успешно проверил все источники и затем остановился на оборванном блоке
координат. Поэтому версия не зарегистрирована и не помечена готовой. Отдельный
Эксперименты 655–657 проверили увеличение длины, один уровень фрагментов и
рекурсивное деление. Последний механизм прошёл малый smoke, но production
оказался в 2–4 раза медленнее жёсткого лимита и уже дал terminal failures в
13/16 сегментов. Поэтому полная версия 634 не будет публиковаться путём
ослабления gate. Эксперимент 660 сохраняет тот же строгий канонизатор, публикует
41 691 надёжное изображение как `OCR_AVAILABLE` и помечает остальные 7 765 как
`OCR_UNAVAILABLE` без OCR-полезной нагрузки.
