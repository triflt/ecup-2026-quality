# Предварительный аудит прямого квантованного 27B-маршрута

Дата: 2026-08-24. Статус: CPU-only feasibility gate; GPU не запускался.

## Проверяемый механизм

Эксперимент не пытается ещё раз дистиллировать 27B в 4B. Он проверяет, можно
ли запускать уже принятый офлайн-сигнал Qwen3.6-27B только для категории
«Легковоспламеняющиеся» в weight-only 4-bit или 3-bit виде. Научный контроль —
BF16-адаптер 654 и фиксированный маршрут 659; порог и веса смеси не меняются.

## Жёсткие ограничения

- ZIP решения: не более 5 GB;
- сжатый Docker-образ: не более 15 GB;
- Qwen3.6-27B отсутствует в зафиксированном списке общих 2B/4B-моделей среды;
- следовательно, дополнительные веса должны находиться либо в ZIP, либо в
  собственном Docker-образе.

## Измерение официального checkpoint

Для [Qwen/Qwen3.6-27B](https://huggingface.co/Qwen/Qwen3.6-27B) получен список
15 `safetensors`; размер каждого взят без скачивания весов из HTTP-заголовка
`x-linked-size` официального репозитория. Сумма — `55 563 006 400` bytes,
или `51,747 GiB`.

Абсолютные нижние границы, если гипотетически квантовать каждый bit checkpoint
без какой-либо служебной информации:

| схема | только биты весов | GiB | остаток до 15 GB image |
|---|---:|---:|---:|
| 4-bit | 13 890 751 600 bytes | 12,937 | менее 2,063 GiB |
| 3-bit | 10 418 063 700 bytes | 9,703 | менее 5,297 GiB |

Реальный payload больше: нужны scales/zero-points, метаданные и часто
неквантованные vision/projector или чувствительные слои. В Docker дополнительно
нужны CUDA runtime, PyTorch, Transformers, загрузчик изображений и код решения.
Квантованные веса обычно плохо дополнительно сжимаются как Docker layer.

## Предварительный вывод

1. ZIP-маршрут невозможен и для 4-bit, и для 3-bit: даже теоретический минимум
   превышает лимит 5 GB примерно в 2–2,8 раза.
2. 4-bit custom image не допускается к GPU-smoke без фактического доказательства
   размера готового сжатого image `<=15 GB`: математический минимум оставляет
   слишком мало места для обязательного runtime.
3. 3-bit можно открыть только при наличии заранее собранного мультимодального
   runtime, точного compressed-size audit и поддерживаемого kernel. Нельзя
   считать текстовый 3-bit loader доказательством совместимости с этой VLM.
4. Если package gate пройден, следующий этап остаётся узким: восемь строк для
   logit parity и времени, затем frozen folds 0/3 без обучения. Gate требует
   сохранения знака AP/Macro относительно BF16, agreement `>=0,98`, отсутствия
   новых FN и прогноза полного времени `<38` минут.

Этот аудит не является научным отклонением 27B: 659 уже доказал её полезный
сигнал. Он проверяет только возможность честно доставить этот сигнал в
ограниченный submission runtime.
