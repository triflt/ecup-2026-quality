## Часть 1. Анализ новых экспериментов (360–490)

### Новый чемпион: 400_qwen35_category_routed_adapters
- Схема: исходный Qwen3.5-адаптер `190` для БАД + адаптер `260` только для легковоспламеняющихся, пороги и приоры заморожены.
- **Public Macro F1 = 0.8922900011** (+0.00037 к 190). Направление подтвердилось, но локальная оценка переоценила перенос (locked nested давал +0.0082, replay +0.0023) — разница статистически ненадёжна для Private.

### Критический внешний фактор: 490_evidence_grounded_explanations
Финальная ручная оценка требует конкретных доказательств из карточки. Текущий рендерер 190/400 имеет четыре шаблонных комментария без полей товара, поэтому качество объяснений остаётся отдельным риском независимо от Macro F1.

### Вывод по треку моделей
Классификационный сигнал вышел на плато (~0.892 Public): все локальные идеи дают ±0.003 и не переносятся надёжно. Дальнейшие чистые модельные экспы (480 и т.п.) имеют низкое ожидание. Два реальных рычага: (а) качество обоснований (490), (б) **новые данные** (обогащение датасета) — см. Часть 3.

## Часть 2. Независимый аудит пайплайна данных и валидации

Числа ниже получены отдельным аудитом CSV и validation manifests. Локальные
промежуточные файлы не являются частью публичного контракта репозитория.

### Что в порядке ✅
1. **Целостность датасета**: SHA-256 исходного CSV совпадает с registry (`competition_train_v1`, immutable). 12 971 строка, 7469 БАД / 5502 ЛВ.
2. **folds.csv (grouped_text_v1)**: покрывает ровно все 12 971 id, **0 расхождений** меток и категорий с data.csv.
3. **Стратификация фолдов идеальная**: БАД|0 = 381×5, БАД|1 = 1113/1113/1113/1113/1112, ЛВ|0 ≈ 1061±1, ЛВ|1 = 40/40/39/40/39. Перекоса нет.
4. **Connected-family инфраструктура** (`connected_family_guard_v2`, `connected_family_repeated_v1`) покрывает все 12 971 строк, есть флаги `safe_for_selection`, компоненты считаются union-find по точному тексту/имени/первому изображению — методологически грамотно.

### Находки ⚠️ (не баги, но риски, о которых надо помнить)
1. **group_hash ≠ семейство по имени.** 272 нормализованных имени имеют >1 group_hash; 49 хешей покрывают несколько имён. Группировка тоньше/иная, чем «одинаковый товар». Если где-то group_hash трактуется как «семейство» — это неверно.
2. **Утечка по семействам в grouped CV**: 236 из 1843 мульти-семейств (по нормализованному имени) распределены между разными фолдами (200 семей на 2 фолда, 27 на 3, 6 на 4, 3 на 5). Это ~500+ строк, у которых близнец обучается в другом фолде. Команда это частично знает («recurrence/memory»), но в locked_190_nested_v1 протоколе явной защиты именно от name-duplicates я не увидел — connected-guard строится отдельно и не все экспы его применяют.
3. **68 семейств с противоречивыми метками** (одно имя — разные label). Это шум разметки; он же объясняет часть «странных» ошибок ЛВ.
4. **ЛВ|1 всего ~198 строк на весь датасет** (39–40 на фолд): любая метрика по ЛВ-ban имеет разброс ±1 объект = ±0.025 F1. Отсюда, вероятно, и «переоценка переноса» в 400/410/420.

### Рекомендации по валидации
- Добавить в locked-протоколы обязательный **name-family disjoint holdout**: хотя бы один сплит, где все 1843 мульти-семейства целиком в одной стороне. Ожидаемая честная цифра будет ниже 0.93 — но именно она ближе к Private, если в hidden есть дубликаты.
- Для ЛВ считать bootstrap-CI по объектам (n=198), а не по фолдам; любые дельты < ±0.03 по ЛВ не интерпретировать.
- Противоречивые 68 семей: пометить `label_conflict=true` и исключить из selection-наборов (guard уже умеет `safe_for_selection`).

## Часть 3. Обогащение датасета большой VLM (~400B): гипотезы и план

Общий принцип: 400B используем как **офлайн-учителя** (разметка/извлечение/генерация), инференс остаётся на Qwen3.5-9B/Qwen3-VL — бюджет и лимиты контура не страдают. Каждый продукт — новая версия датасета в registry с provenance (immutable, как competition_train_v1).

### H1. Псевдо-разметка реальных карточек-кандидатов (главная гипотеза)
Собрать (парсингом/выгрузкой) реальные карточки тех же двух категорий с маркетплейса — тысячи штук, особенно **легковоспламеняющиеся** (у нас всего 198 позитивов!). Прогнать через 400B с официальными правилами → вероятности бан/не бан. Фильтр: согласие с ансамблем-чемпионом (190/400) + высокая уверенность учителя. Итог: +5–20k строк, из них критично +сотни ЛВ-позитивов.
- Ожидание: основной прирост именно на ЛВ (сейчас F1 ЛВ — самое слабое место и источник всего шума).
- Риск: сдвиг распределения относительно hidden → держать долю синтетики ≤30% и валидировать на чистом grouped-сплите.

### H2. Контролируемая генерация пограничных случаев (hard negatives/positives)
400B генерирует правдоподобные карточки **точно на границе правил**: мангал с углём/без, горелка с баллоном/без, пьезоподжиг, БАД с «лечебными заявлениями»/обычная косметика. Метка известна из конструкции примера. Это прямой тренажёр под главную путаницу модели.
- Дёшево, масштабируемо, идеально для контрастива/эмбеддера (связка с нашей B-волной: синтетические пары «почти одинаково, но метка разная»).

### H3. Извлечение атрибутов → структурные признаки + чистка семейств
400B извлекает по каждой карточке атрибуты: {газ/уголь/пьезо/баллон, форма выпуска, дозировка, лечебные заявления, бренд+артикул}. Использования:
- атрибутные правила в текстовую голову (как 450, но с VLM-точностью);
- **семействование по атрибутам вместо имени** — чинит найденные аудитом проблемы (236 межфолдовых семей, 272 имени с разными хешами);
- мажоритарная чистка 68 противоречивых семей.

### H4. Дистилляция вердиктов + обоснований в Qwen3.5
Разметить весь train (и псевдо-данные из H1/H2) софт-метками 400B → дистиллировать в текущие адаптеры (KD-loss поверх CE). Даёт калиброванные вероятности для rank-fusion и устойчивость к шуму 68 конфликтных семей.

### H5. Evidence-spans для 490 (разблокирует финал)
400B извлекает **точные спаны текста и визуальные факты** («на фото баллон 220 г», «в составе мелатонин 10 мг») для каждого товара → детерминированный рендерер цитирует их в комментарии. Закрывает требование оргов «комментарий должен ссылаться на конкретику карточки» без LoRA-генерации. Gate: 189+/200 строгих pass на блендед-выборке.

### Приоритет и стоимость
| # | Гипотеза | Эффект | Стоимость | Приоритет |
|---|----------|--------|-----------|-----------|
| H5 | Evidence-spans | снимает риск непрохождения финала | низкая (1 проход 400B + рендерер) | **P0** |
| H1 | Псевдо-разметка реальных карточек | +ЛВ-позитивы, главный прирост F1 | средняя (сбор + разметка) | **P0** |
| H2 | Синтетические пограничные случаи | тренировка границы решений | низкая | P1 |
| H3 | Атрибуты/семействование | чистка данных + признаки | средняя | P1 |
| H4 | Дистилляция | калибровка + робастность | высокая | P2 |
