# Версионированные выборки для валидации

`registry.toml` — единый реестр версий валидации. В зафиксированной версии
`grouped_text_v1/` файл `folds.csv` распределяет все обучающие `id` по пяти
групповым фолдам, `basket.csv` содержит внешний фолд 4 для быстрой проверки
дорогих моделей, а `manifest.json` фиксирует версию данных, число строк и
контрольные суммы. Тексты и изображения не публикуются; `id` соединяются с
локальными данными `competition_train_v1`.

Воспроизведение из исходной таблицы:

```bash
python3 validation/build_folds.py --data /absolute/path/data.csv
```

По умолчанию команда не перезаписывает существующую версию. Для новой корзины
задайте другие пути и `--evaluation-version`, затем добавьте запись в
`registry.toml`. Флаг `--force` предназначен только для осознанного точного
воспроизведения с последующей проверкой контрольной суммы.

Для точного восстановления исторических фолдов из локального OOF-кэша
используется `freeze_existing.py`. Путь к кэшу не хранится в Git.

После пересборки контрольные суммы и число строк в
`grouped_text_v1/manifest.json` должны совпасть. Существующая версия неизменяема:
при изменении фолдов создаются новый каталог и новая запись в реестре, а
конфигурация эксперимента явно переключается на новый `evaluation_version`.

Для локальных голов, которые предсказывают остаточную ошибку или метрику,
используется `component_transfer_gate_v4`. Он сохраняет численные требования v3,
но выбирает один протокол устойчивости с учётом детерминированности модели и
повторно вычисляет решение из канонических файлов, связанных через SHA. Это
исключает запуск по неполному или вручную изменённому JSON с решением.
